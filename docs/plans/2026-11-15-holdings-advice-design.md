# 持仓分析与建议 — 设计文档

日期：2026-11-15

## 背景与目标

`investment_advice` 每天让模型自选标的给 1～3 条建议，和我实际持有什么无关。本设计新增一条独立任务：每天读取持仓配置，让模型逐个检查持仓，给出加仓、持有、减仓或清仓的建议，再加一段组合层面的判断。改了持仓只需要改配置文件。

## 已确认的需求

- 持仓品种：A 股个股和场内 ETF、港股、美股和美股 ETF、加密货币、黄金和期货、现金。
- 配置里记数量和成本价。
- 现价由程序从行情接口取，连同盈亏比例和占比写进提示词。（最初定的是模型自己联网搜索，2026-11-15 试跑后改回程序取价：模型查到的黄金 ETF 现价是四舍五入过的 7.95，实际收盘 7.954。）
- 市值、盈亏、占比由程序计算，模型不做这些计算。
- 成本价和盈亏发给模型。数量和金额不发。
- 持仓配置和持仓报告不进 git：仓库是公开的，`advice/` 每次都会被推上去。
- 只在能联网搜索的后端上运行，沿用 `build_investment_llm_client()`。

## 非目标

- 不记交易流水，不自动下单，不画收益曲线。
- 持仓建议不写入 `advice/`，不进入到期结案、周回溯、月回溯。
- 期货按名义市值计仓位，不处理保证金和杠杆。
- 不支持场外基金。
- 不做多角色辩论，不做第二遍核对。每次 cloud agent 调用约 7 分钟，第一版只调用一次。

## 调研结论

调研了 portchecker、daily_stock_analysis、TradingAgents 等项目，以及几篇关于大模型做投资判断的偏差研究。采纳的做法：

- 持仓数字由代码算，模型只负责判断。取不到价的持仓单独列出，不按零计入。
- 每个持仓可以写持有理由和卖出条件，模型每天对照检查。
- 动作有明确定义。加仓、减仓、清仓必须附带有日期和链接的新事实，或被违反的规则。
- 默认动作是持有。每天复查同一批持仓，要求模型果断会逼着它天天找理由调仓。
- 仓位偏好写成可检查的规则（单票上限、现金下限），不用「你是保守型投资者」这类人设。
- 上一次的结论只放动作，并标明是模型此前的判断、可能是错的。整段放进去会被照搬。
- 研报评级、目标价和 `advice/` 里的历史建议都标明是观点，不能当作结论的依据。
- 研究显示买入价会影响模型的买卖决策。成本价按需求发给模型，但提示词要求先做往后看的判断，成本价和盈亏只能出现在「执行」一节。

## 配置

持仓写在 `config/holdings.toml`，已加入 `.gitignore`。仓库里只有示例 `config/holdings.example.toml`。

```toml
[cash]                 # 现金和货币基金，按币种填金额：CNY / USD / HKD
CNY = 50000

[rules]                # 都可以不填
max_position_pct = 20  # 单个持仓的市值占比上限
min_cash_pct = 10      # 现金占比下限
horizon = "一年以上"

[[holdings]]
symbol = "600519"
market = "SH"          # SH / SZ / HK / US / CRYPTO / FUT，决定币种
name = "贵州茅台"
quantity = 100
cost = 1500            # 每股买入均价
thesis = "高端白酒龙头，分红稳定"   # 可选
exit_when = "连续两个季度营收负增长" # 可选
```

币种由 `market` 决定：SH、SZ、FUT 是人民币，HK 是港币，US 和 CRYPTO 是美元。期货可以填 `multiplier`（合约乘数），默认 1。实物金、积存金可以记成 `AU0`，数量填克数。

每次运行都重新读文件，改完持仓不用重启常驻进程。

校验不过时列出全部问题，不调用模型：缺字段、数量或成本不是正数、market 不认识、symbol 重复、symbol 没加引号、写了不认识的字段。

## 数据流

新增 task `holdings_advice`，每天 08:40 运行，不加入任何复合组。

```
holdings_advice:  HoldingsAdviceStep | HoldingsNotifyStep
```

1. 读配置并校验。
2. 从新浪取美元、港币兑人民币汇率（`fx_susdcny`、`fx_shkdcny`）。只有人民币持仓时不取。
3. 取每个持仓的现价（`fetchers/holding_quotes.py`）：SH / SZ / HK / US / FUT 走新浪行情，CRYPTO 走币安。用现价算市值、盈亏、市值占比、币种分布，并检查规则。所有持仓都没取到现价时不调用模型。
4. 拼提示词，调用模型。提示词包含：
   - 每个持仓的代码、名称、市场、币种、成本价、现价和交易日、盈亏比例、市值占比、持有理由、卖出条件
   - 现金占比、规则，以及程序检查规则的结果
   - 这些标的在 `advice/` 里未到期的建议，标明是模型此前的判断
   - 上一次每个持仓的动作（今天之前、7 天内最近一份报告），标明可能是错的。同一天重跑不拿当天上一轮的结果当「上次」
   - `advice/lessons.md` 最近 10 条经验
5. 解析回复。每个持仓一块，字段是 `action`、`target_weight`、`summary`，正文四节：依据、执行、风险、什么情况下改变结论。最后一块是「组合」。模型多写的价格字段不采用。
6. 校验每条建议。
7. 报告存到 `data/holdings/YYYY-MM-DD.md`，动作存到同名 `.json`，再推送企微。

「今天」在每次 `process()` 里取，step 接收 `today_fn`。

## 校验

行情不合格时，该持仓标为「现价不可用」，不计入总资产、占比和盈亏，提示词里注明程序没有取到，建议仍然保留：

- 接口没有返回这个代码的报价
- 现价不是正数（A 股、港股开盘前现价是 0，这时用昨收）
- 报价里没有交易日，或交易日早于今天 10 天以上

建议不合格时，该持仓列入「建议未通过校验」并注明原因：

- `action` 不是加仓、持有、减仓、清仓之一
- 「依据」一节为空
- 动作不是持有，「依据」里没有链接，也没有规则依据。规则依据只支持减仓和清仓：该持仓超过单票上限，或现金低于下限（这时减哪只都算）。超出规则不能当作加仓的理由

本地报告里每个现价都带交易日和来源（新浪行情或币安）。盈亏 = 市值 − 配置里的成本 + 持有期（`since` 之后除息）的税前现金分红，分红由程序从接口拉取；不含已实现盈亏和送转股。

## 隐私边界

- 发给模型：成本价、现价、盈亏比例、市值占比、现金占比、规则检查结果、持有理由、卖出条件、规则。不发数量和金额。
- 企微推送：程序写的部分只有比例（占比、盈亏百分比）和现价。模型写的「执行」一节可能提到成本价。
- 本地报告：包含数量、市值、盈亏金额。
- 可选环境变量 `HOLDINGS_WEBHOOK_URL`（逗号分隔），未配置时用默认 webhook。

## 推送

- 第一条是总览：总盈亏比例、现金占比、币种分布；每个持仓一行动作、占比、盈亏和一句话结论。动作和上次不同的标出「上次：…」。末尾列出超出规则的地方、现价不可用的持仓、未通过校验和未覆盖的持仓。
- 动作不是持有，或动作和上次不同的持仓，各发一条详情（四节正文）。持有且没变的只出现在总览里，详情看本地报告。
- 最后一条是组合层面的建议。
- 每条末尾附「模型生成，非投资建议」。

## 失败处理

- 配置文件不存在或校验不过：不调用模型，推一条说明。
- 汇率取不到：当天不分析，推一条失败说明。
- 模型调用失败：推一条失败说明。
- 回复里一条合法建议都没有：原文存到 `data/holdings/YYYY-MM-DD-raw.md`，不写动作记录，不覆盖当天已有的报告，推一条失败说明。
- 模型漏掉某些持仓：保留合法部分，总览末尾注明。

## 验收

单测不联网、不调真实模型。

- 配置校验一次报出全部问题；symbol 重复、未知字段、未知市场都会报错
- 多币种的成本占比、市值、盈亏、市值占比、币种分布计算正确
- 现价不可用的持仓不计入总资产，其余照常
- 超出单票上限、低于现金下限会被列出
- 提示词包含成本价、现价、盈亏比例和占比，不包含数量和金额
- 各市场的新浪报价字段解析正确；过期、缺日期的报价不用；取价失败不抛异常
- 所有持仓都没取到现价时不调用模型
- 提示词里的上一次结论和未到期建议都带「可能是错的」说明
- 回复解析能处理代码围栏、`0700.HK` 这类写法、未知标题
- 非持有动作没有链接也没有违规时不通过校验
- 推送不包含金额，本地报告包含
- 同一个 step 对象在配置修改后读到新持仓
- 配置缺失、汇率失败、模型失败各推一条说明，前两种不调用模型
- cron 为每天 08:40，`holdings_advice` 不在任何复合组里
